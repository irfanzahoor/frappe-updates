# Daily Update — 2026-11-25

## Frappe Framework v16.61.0 — 24 November 2026

The first release inside the last 24 hours: Frappe Framework v16.61.0 landed on 24 November (09:39 UTC), a week after v16.60. No new ERPNext release came with it, and there is no new blog post or forum announcement.

### What is new

1. **Frappe Framework v16.61.0 — 24 November 2026**
   - 7 features and 35 bug fixes in the core, plus Flow, Email and Printing sections.
   - Custom form buttons can now use styles such as `primary` or `danger`; existing buttons keep the default style.
   - Maintenance mode now lets users **view** data by default while blocking changes. Setting `allow_reads_during_maintenance` to `0` in site config restores the old behaviour of blocking everything.
   - A **Preview** button on saved Letter Head forms shows the rendered header and footer before printing.
   - A **Show on Desktop** setting for Studio Apps — published apps can be hidden from the desktop and app switcher while staying available at their route.
   - **Flow:** visitors who are not signed in can now chat with Flow Agents marked Public (hourly guest limit in Flow Settings), and Flow shows an approval notice before using the site's Grove key for AI features.
   - The AI assistant can now view images returned by its tools, and file responses — including PDFs — include a description.
   - URL previews can use a chosen size, capture the full page, and wait for a page-specific readiness check.
   - **Printing:** role restrictions on Print Format — admins can control which formats users can select for printouts, PDFs and email attachments. Holding Ctrl while scrolling over a print preview zooms it.
   - **Users & Permissions:** bulk **Add Roles** / **Remove Roles** actions on the User list, without replacing other roles.
   - **Performance:** the Studio editor uses smaller undo copies and caps undo history at 20 MB — less memory use, fewer crashing tabs on large pages.
   - **Security:** GitPython updated to 3.2.1 (fixes known vulnerabilities); private Workspace pages are now restricted to their owner and Workspace Managers; Web Form data loading is limited to the document type configured for the form; email creation is restricted to System Users.
   - **Email:** Outlook.com mailboxes blocked from sending through other apps can now connect for receiving; encoded and multi-line attachment filenames are decoded properly; inline images get generated filenames and empty attachment wrappers are dropped, reducing spam-filter warnings.

### What it means for you

- **If you run v16 sites:** a routine patch, low risk — update on staging first as usual. Two behaviour changes to note: users can now *read* data during maintenance mode by default (set `allow_reads_during_maintenance` to `0` if a client expects the old total block), and private Workspaces are now truly private — check any client setup that relied on shared private workspaces.
- **If you use Flow:** public agents are a new option for guest-facing chat on a site — set the hourly guest limit before enabling. The Grove-key approval notice is a good governance step for client sites.
- **If you build print formats:** Print Format role restrictions are worth using on client sites where only certain roles should pick a format.
- **No ERPNext release today:** ERPNext's latest is still v15.126.0 (22 Nov), so there are no ERPNext-side changes to test — this is a Framework-only update.
